# Codex Galaxy 1.9.9

## Official to API auth isolation

- Fixed official → API switches that could roll back to the official account until the user manually logged out and ended the Codex process.
- API switching now removes the live official `auth.json` instead of preserving the in-memory official OAuth session. The captured official login remains encrypted in Galaxy and is restored when switching back.
- Official auth files with an empty `OPENAI_API_KEY` field are no longer misclassified as legacy API authentication; only a non-empty API key triggers the legacy-auth guard.
- If Codex rewrites official auth after an API switch, launch verification reports `api-official-auth-present` and rolls the transaction back instead of claiming that the API switch succeeded.

## Preserved behavior

- Provider-scoped API credentials and `model_catalog_json` remain available to the selected API profile.
- Local Codex Home, SQLite indexes, rollout history, official snapshots, and recoverable rollback backups remain preserved.
- The 1.9.8 fix for reserved `[model_providers.openai]` overrides and the misleading Windows `config_load` screen remains included.
- Windows sandbox settings remain isolated by profile, and graceful shutdown still tolerates a `gracefulTerminate` callback failure before using the verified fallback.
- The redacted 本地日志 continues to record switch failures with UTC and local timestamps without storing credentials or chat bodies.

## Documentation and verification

- Updated both READMEs, the in-app Chinese/English guide, release metadata, tests, and the release checklist together.
- `npm run check:docs` and the full automated test suite must pass before publication.

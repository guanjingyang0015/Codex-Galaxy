# Codex Galaxy 1.9.7

## 发布记录修复

- 修正当前安装版本的发布记录，使已发布版本显示真实的 GitHub 提交和 Actions 信息，而不是“本地版本/Actions 未知”。
- 保留 1.9.6 的文档同步门禁：每次版本更新都必须同步更新中英文 README、软件内中英文使用教程、发布说明、发布记录、测试和安装包。
- `npm run check:docs` 和 `npm run stamp:release` 继续作为 CI 发布前检查；文档或版本内容不同步时，构建流程会在安装包任务前失败。

## 切换修复与本地日志

- Windows 原生优雅关闭函数现在同时兼容同步和异步返回值，修复官方账号切换时报 `gracefulTerminate(...).catch is not a function` 的问题。
- 切换、刷新、清理和其他 IPC 操作失败时，Galaxy 会在 `~/.codex-galaxy/logs/galaxy.log` 保存 UTC 时间、本地时间、操作、错误类型和脱敏错误信息。
- 顶部“日志”可以查看最近日志、打开日志文件或复制日志；日志不会记录 API Key、OAuth、聊天正文或请求体。
- 使用教程补充了 API → 官方、官方 → API 的完整操作步骤。

## 官方切换与模型目录

- 官方配置不再继承当前 API 配置中的 Windows sandbox 表；已保存的官方配置保留自己的 sandbox 设置。没有官方快照时，切换会保留当前认证文件供 Codex 完成一次人工官方登录；如果 Windows setup 卡住，可以在提示框明确选择“兼容模式重试”改用 `unelevated` 后端，随后自动捕获并重新验证官方状态。
- API 模型为空、属于可解析的模型家族，或填写了具体 GPT 型号时，Galaxy 会重新读取中转站 `/models`，保存有界的型号目录，并通过 Codex 原生 `model_catalog_json` 格式提供可选型号；填写的具体 GPT 型号仍保持为默认型号。
- 如果中转站只返回一个型号，或 Codex Desktop 因官方账号门控隐藏自定义型号，Galaxy 不伪造不可用的官方模型；应使用命令行模型列表或中转站目录确认实际可用型号。

## 兼容性与安全

- 延续 1.9.5 的切换误报修复和完整线程历史恢复。
- 不删除 `config.toml`、本机 Codex 数据、SQLite 数据库或聊天文件。
- API Key、OAuth、完整聊天记录和生产配置不会写入文档、日志、测试结果或 Git。

## 发布边界

- 只有测试、文档检查、构建、GitHub Actions、公开 Release、标签目标和安装包资产全部验证通过后，版本才算正式发布。
- Windows 安装包未签名；macOS 安装包由 GitHub Actions 构建验证。

# Codex Galaxy 1.12.0

## Multi-API audits and model identity evidence

- Added parallel background auditing for all saved API profiles with locally encrypted keys.
- The configured Model ID is treated as the expected model. Galaxy separately records the model sent in the request and the model declared by Responses output.
- Model identity is a critical 40-point category. Exact matches receive full credit; same-family aliases receive partial credit; a different response-declared model caps the total at 49 points; missing model evidence is shown as unverified and cannot receive a high score.
- Detailed reports now show `/models`, expected/requested/observed model IDs, Responses structure, response IDs, usage fields, each reasoning effort, timeout/stability evidence, latency, score contribution, and pass/partial/fail status.
- This is still black-box consistency evidence. A relay can falsify response metadata, so Galaxy does not claim that a high score proves official upstream origin.

## Ranking usability

- Ranking numbers now include the points unit.
- Every ranked provider is clickable. A validated provider homepage is preferred; otherwise Galaxy and the ranking service fall back to the tested HTTPS API host.
- Ranking rows show expected model and response-declared model when available.
- The server independently recalculates scores and model verdicts instead of trusting client-provided totals or verdict labels.

## Scoring design

- Model identity: 40 points.
- Model catalog and Responses protocol: 25 points.
- Reasoning-effort canaries: 15 points.
- Stability and timeout behavior: 10 points.
- Successful-request latency: 10 points.
- Critical model mismatch cap: 49 points; unverified identity cap: 59 points; listed-only evidence cap: 79 points; no configured expected model cap: 80 points.

The structure follows mature evaluation patterns: deterministic assertions, weighted components, explicit thresholds, critical gates, and evidence-first reporting rather than a single unexplained score.

## Safety and compatibility

- Saved API keys remain in Electron `safeStorage` and never cross renderer IPC.
- Public ranking receives only bounded redacted metrics. API keys, prompts, complete outputs, OAuth, and chat histories remain excluded.
- The dedicated Cloudflare Tunnel, Worker, Tencent loopback ranking service, Windows sandbox behavior, `model_catalog_json`, and existing account-switching paths remain unchanged.
- The redacted local log and `gracefulTerminate(...).catch(...)` recovery boundaries remain unchanged.

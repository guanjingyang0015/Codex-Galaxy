# Codex Galaxy

[English](README.en.md) | 简体中文

Codex Galaxy 是运行在用户电脑上的 Codex 多账号切换与项目续接桌面程序。它让同一台电脑上的本地 Codex 线程在官方订阅账号、中转 API 和其他兼容 provider 之间继续使用。

典型场景：项目用官方账号 A 和 GPT-5.5 做到一半，额度不足后选择中转账号 B，一键同步并切换，再用 GPT-5.6、DeepSeek 或其他模型继续原线程。历史消息保持原样，只有当前账号、provider 和后续使用的模型发生变化。

## 核心能力

- Windows 与 macOS 共用一套本地 Electron 桌面程序
- 配置任意数量的官方账号或中转 API
- 不需要官方账号也能添加并切换多个纯 API；API 凭据之间切换时不会生成或依赖官方 OAuth 快照
- 账号名称可在创建后随时修改，改名不影响凭据和线程
- 选择账号后单击“切换并打开 Codex”
- Galaxy 工作台左上角品牌区显示简洁版本号；Windows 外部 Codex Desktop 前台时，右上区域显示可穿透鼠标的 `Codex Galaxy x.x.x` 标识，Galaxy 不修改 Codex 安装文件或聊天数据
- 自动安全关闭新版 `ChatGPT.exe` 外壳、Codex Desktop 后台 `app-server` 和旧版 Codex Desktop，完成切换后重新打开；普通 `codex resume` CLI 不会被误关
- 检测到 Codex 正在运行时先提醒任务可能被中断，由用户选择继续或取消
- 显示关闭、备份、账号切换、线程 provider 同步、项目列表刷新和启动进度
- 切换完成后自动打开 Codex；也可从线程列表直接恢复指定项目
- 使用原线程 ID 和完整本地历史，不复制或伪造云端聊天
- API 模型 ID 可留空并通过中转站标准 `/models` 自动发现；也可填写 `gpt-*`、`deepseek-*`、OpenRouter 路径或其他兼容模型 ID，不设厂商白名单
- API 账号通过仅监听 `127.0.0.1` 的本地 Responses 网关连接中转站；上游转发使用系统代理网络栈，旧模型压缩请求会使用当前账号模型重试
- Galaxy 配置库中的 API Key 和官方登录快照使用 Electron `safeStorage` 加密，Windows 使用系统加密，macOS 使用 Keychain；激活 API 时只把当前 API Key 写入 Codex 文件凭据 `auth.json`，不会进入 Galaxy 日志、线程内容或渲染器状态
- 整个切换过程按事务执行；失败时恢复凭据、配置、加密库、当前账号标记、rollout、SQLite、本地项目库和网关状态
- 内置“使用教程”，并提供只扫描本机数据的“刷新项目”操作
- 手动刷新和自动切换同步都显示真实条目进度、百分比与完成提醒
- 项目列表只显示 Codex 当前有效根任务，自动排除已归档、已删除、空白和内部子代理记录
- 大型线程采用低内存流式 provider 更新，并自动回收异常退出遗留的失效同步锁
- 合并 Codex 桌面 local thread catalog 与 thread_history，当前聊天没有 rollout 文件时仍可显示项目和最近消息
- 会话 provider 首行在长度允许时原地补丁，切换进度显示预计剩余时间，避免每次切换重写数 GB 历史
- 官方兼容性检查只读取首次检查或发生变化的 rollout；已缓存的历史不再计入等待字节。通过“在 Codex 中继续”打开具体线程时只检查该线程，避免为一次继续操作扫描整本 Codex Home
- 切回官方账号时自动移除中转站写入且不符合官方 Responses 规范的 message ID；合法官方 `msg_` ID、工具调用 ID、正文和顺序保持不变
- GPT 中转自动补齐缺失的图像能力声明；API 账号统一使用独立纯 API 登录态，旧版混合配置首次升级会自动迁移
- 账号区提供 RightAPI 与 ZYG Token 中转站注册地址，一键只复制链接，不自动打开浏览器
- 顶部提供本地插件/插件市场入口，以及归档/删除项目和完成自动化历史的预览、备份后清理
- 切换回滚备份默认保留最近 8 份，较早的 Galaxy 自动生成备份会清理；Codex 原始聊天和账号数据不在此清理范围内

## 工作原理

Codex 的项目线程保存在本机 Codex Home 中。Codex Galaxy 将账号凭据与线程历史分开管理：

1. 关闭 Codex Desktop 的主窗口和新版残留 `app-server`，持续确认全部桌面认证进程退出；普通 `codex resume` CLI 不会被终止。
2. 先扫描已经停止写入的本地 SQLite 和线程文件，保存最新项目记录。
3. 仅在 live 状态确实属于当前槽位时保存其本地授权状态。
4. 恢复目标官方账号快照；API 账号则先启动本地 Responses 网关，再写入指向网关的 provider 配置和明确的 `auth_mode = apikey` 文件凭据。
5. 将根线程的 `session_meta.model_provider` 和 SQLite 目录切换到目标 provider；切回官方时仅移除官方接口不能接受的外部 message ID。已缓存且未变化的历史跳过扫描；从线程入口继续时优先检查当前 rollout。
6. 保持用户/助手历史正文、合法官方消息 ID、工具调用 ID、原模型记录和 subagent 线程不变。
7. 再次刷新目标账号的项目列表，成功提交当前账号标记并重新打开 Codex；启动后延迟复核认证文件，若 Codex 后台回写成其他账号，则再次停止 Codex 并完整恢复切换前状态与网关状态。

因此，A 与 B 看到的是同一本机线程，不是把聊天上传到另一个云账号。模型版本和厂商可以变化，但目标 API 必须兼容 Codex 使用的 OpenAI Responses API 协议。

## 首次使用

1. 只使用中转 API 时，无需登录官方账号；点击账号区的 RightAPI 或 ZYG Token 按钮复制注册地址，粘贴到浏览器完成注册。
2. 打开 Codex Galaxy，点击 `+`，添加一个或多个“中转 API”，填写自定义账号名称、Base URL 和 API Key。模型 ID可留空自动发现，也可手动指定。
3. 需要使用官方账号时，再在 Codex 官方程序中登录，添加“Codex 官方账号”并点击该账号的“捕获”。
4. 在账号列表中选择目标账号，点击“切换并打开 Codex”。
5. 等待进度到 100%，随后在 Codex 中继续工作。“查看详情”只在 Galaxy 中显示线程信息；“在 Codex 中继续”会使用当前选择的账号切换并恢复该任务。

每个官方账号只需首次登录并捕获一次。API Key 输入后只保存在本机加密库；后续编辑账号时 Key 留空即可保留原值。

使用 API 账号时，Galaxy 主窗口关闭后会缩到系统托盘，因为 Codex 需要本地 Responses 网关继续转发请求。完成任务或切回官方账号前请保持 Galaxy 运行；从托盘选择“退出”会停止网关，并可能中断仍在进行的 API 对话。

右上角“刷新项目”只重新扫描本机 Codex 的 SQLite 和线程文件并更新 Galaxy 项目列表。它不会切换账号、执行登录，也不会在账号之间上传或复制聊天。

Galaxy 以现代 Codex 根 `state_5.sqlite` 的可见状态为权威：已归档任务不能再被旧版嵌套数据库复活；没有用户内容的空白任务和内部子代理任务也不会进入项目继续列表。桌面目录仅在存在真实聊天历史时补入当前任务，因此不会为了过滤旧数据而漏掉正在使用但尚无 rollout 路径的桌面对话。

右上角“刷新项目”只重建显示列表，不物理删除 Codex 数据。用户确认不再需要归档/删除任务时，可点击“清理数据”，勾选“已归档/已删除项目”。Galaxy 会先关闭 Codex，将相关数据库、名称索引和 Galaxy 列表复制到备份目录，把归档会话压缩为 `.gz`，再从根数据库、旧数据库、桌面目录和历史投影中删除这些明确的任务 ID；当前未归档任务始终受保护，也不会删除任务 `cwd` 指向的项目文件夹或任何源代码。清理前若 Codex 正在运行，完成或失败后都会尝试重新打开。

## 从旧版覆盖升级

已安装 0.1.0 或后续版本时，不需要手动卸载。使用同一个 Windows 用户直接运行新版安装包即可。安装器使用与 0.1.0 相同的应用 GUID；如果 Codex Galaxy 仍在运行，安装器会提示并自动关闭旧程序，等待退出后再替换文件。若程序无法关闭，安装会停下并允许重试，不会直接覆盖出半安装状态。升级会保留：

- `~/.codex-galaxy` 中的账号名称、API 配置、加密凭据、官方登录快照和 Galaxy 项目索引
- `~/.codex` 中的 Codex 官方配置、项目线程和聊天记录

即使通过 Windows“已安装的应用”手动卸载，当前安装器也不会主动删除上述两个目录。为避免 Windows 系统账号加密边界发生变化，请始终使用原来保存配置的同一个 Windows 用户完成升级；不要把 `.codex-galaxy` 中的加密文件复制给其他用户或其他电脑当作迁移方式。

1.1.0 首次读取旧版 `profiles.json` 时会升级到 schema v3：所有 API 账号统一迁移为独立纯 API 登录，旧版“API 路由 + 官方插件登录”配置不再保留。迁移不会改变加密保存的 API Key、官方 OAuth 快照、聊天或项目数据。旧版官方账号快照即使还没有账号指纹字段，也会从其本机加密内容中安全识别，无需重新捕获。

如果 Galaxy 正在显示账号切换进度，请先等待切换成功或自动回滚结束，再启动安装包。使用 API 时也应先完成 Codex 当前任务，因为安装器会关闭包括托盘在内的旧版网关。普通空闲运行状态不需要手动关闭。

## 本地数据

- Codex 数据：默认读取 `~/.codex`
- Codex Galaxy 数据：默认写入 `~/.codex-galaxy`
- 账号配置：`profiles.json`，不含明文密钥
- 加密凭据：`vault.json`
- 本地线程索引：`conversation-library.json`
- 同步备份：Codex Home 下的 `backups/` 与 `backups_state/`

可使用 `CODEX_HOME` 和 `CODEX_GALAXY_HOME` 指定隔离目录。不要提交这些目录、`auth.json` 或任何真实 API Key。

## 本地开发

要求 Node.js 22 或更高版本。

```powershell
npm ci
npm run icons
npm test
npm start
```

构建 Windows 安装包：

```powershell
npm run dist:win
```

构建 macOS Intel 与 Apple Silicon 安装包：

```bash
npm run dist:mac
```

GitHub Actions 会分别生成 Windows x64、macOS x64 和 macOS arm64 构建产物。macOS 行为仍应在真实 Intel 与 Apple Silicon 机器上验收。

## 已知边界

- 官方账号首次登录必须通过 Codex 官方 OAuth 流程，Codex Galaxy 不绕过登录或验证码。
- 中转 API 必须兼容 OpenAI Responses API；只兼容 Chat Completions 的接口不能直接使用。
- 历史中存在上游 `encrypted_content` 时，跨 provider 可能无法复用对应的加密推理内容；程序会在对应任务详情中显示兼容性说明。
- Codex 更新可能调整本地 SQLite 或 rollout 格式，线程同步实现需要随官方格式变化维护。
- 账号切换会修改本机 Codex 的 `config.toml`、`auth.json` 和根线程的 provider 路由；切到 API 时保留线程内部模型，切回官方时仅在需要时恢复官方模型。历史消息不会被改写，程序会先备份并在失败时回滚。

## 安全与许可证

Codex Galaxy 只在 API 模式监听本机回环地址 `127.0.0.1:43821`，不接受局域网或公网连接，不上传聊天到 Galaxy 服务，也不修改 Codex 应用本体。API Key 仅从本机加密库读取并作为上游授权转发，不写日志或界面状态。应用内的中转站注册链接含作者推广参数，用户可自行选择是否使用。项目使用 MIT 许可证。账号切换和 provider 同步边界参考了 [CodexPlusPlus](https://github.com/BigPizzaV3/CodexPlusPlus) 的公开实现；线程恢复行为基于 OpenAI Codex 的公开 CLI 接口与 [Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server)。
